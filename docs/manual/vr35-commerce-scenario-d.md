# VR-35 — Scenario D: от покупки до использования ресурса

## Автоматический сценарий

PlayMode-тест `ScenarioD_FromTabletPurchaseToPlantingPhysicalSeed` использует
production-конфигурацию `Startup` и проходит один физический саженец через весь
commerce flow:

1. На левом VR-контроллере открывается планшет и выбирается
   `product.basilseed` за 5 единиц валюты.
2. Двойное подтверждение в одном кадре списывает баланс `100 → 95` ровно один
   раз и создаёт одну запись очереди.
3. После детерминированной подготовки нулевого баланса покупка другого товара
   отклоняется без изменения Economy, очереди, Inventory или Delivery Box.
4. `Delivery Box` материализует покупку и переводит запись
   `Pending → Available`.
5. Настоящий XRI select забирает предмет: запись становится `Claimed`, а общий
   `PlayerInventory` получает одну единицу. Повторный callback ничего не
   дублирует.
6. Тот же `SeedItemInstance` передаётся production planting receiver. Саженец
   расходуется, Inventory возвращается к нулю, а planting slot переходит в
   `Growing`; запись доставки остаётся `Claimed`.

## Ручная проверка на Quest 3

1. Запустить `Assets/_Project/Scenes/Startup.unity` на поддерживаемом runtime.
2. Открыть магазин на левом контроллере, выбрать саженец базилика и быстро
   дважды нажать `КУПИТЬ`. Баланс должен уменьшиться только на 5.
3. Убедиться, что в Delivery Box появился один физический саженец. При
   заполненных слотах дополнительные покупки должны оставаться в очереди и
   появляться по FIFO после освобождения места.
4. Израсходовать оставшийся баланс и попытаться купить другой товар. Должен
   появиться статус «Недостаточно средств», без нового предмета и записи
   доставки.
5. Взять купленный саженец контроллером. Он должен исчезнуть из ящика только
   один раз и остаться в руке после отпускания.
6. Поместить этот же саженец в planting socket. Грядка должна перейти в
   `Growing`, а физический саженец — израсходоваться.
7. Повторный захват или callback не должен повторно списывать деньги, выдавать
   item или менять уже закрытую запись очереди.
8. Повторить ключевые действия после pause/focus loss: устаревший ввод не
   должен завершать покупку, получение или посадку.

Аппаратные tracking, grab/haptic и читаемость UI проверяются вручную;
атомарность, identity физического предмета и downstream use покрыты PlayMode.
