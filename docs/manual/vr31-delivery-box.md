# VR-31 — Delivery Box и получение покупок

## Поведение

`Delivery Box` создаётся при запуске рядом с основной композицией теплицы и
содержит три контролируемых слота. Он является только физической проекцией
`PendingDeliveryLedger`: удаление или потеря GameObject не удаляет покупку.

1. Успешная покупка создаёт отдельную запись `Pending`, включая одинаковые товары.
2. На следующем Unity tick ящик занимает свободные слоты строго по FIFO.
3. Только после успешного создания grab-представления запись становится `Available`.
4. Захват через `XRGrabInteractable` вызывает атомарный `Claim` в общий
   `PlayerInventory`.
5. Успешный claim освобождает слот и оставляет предмет в руке. Саженец получает
   `SeedItemInstance`, удобрение — `FertilizerItemInstance`, поэтому их можно
   сразу использовать в существующем gameplay.

При заполненных слотах остальные записи остаются `Pending`. Ошибка создания
представления также сохраняет `Pending`; ошибка inventory claim сохраняет
`Available` и повторяет ту же команду с неизменным context. Уничтоженное до
claim представление восстанавливается из snapshot очереди.

## Ограничения MVP

Production-каталог продаёт физические ресурсы по одной единице. Запись с
`quantity != 1` не материализуется и остаётся в очереди с русской диагностикой:
один физический объект не должен неявно представлять несколько расходуемых
единиц. Batch-handoff требует отдельного контракта.

Delivery Box блокирует reconciliation и получение при pause/focus loss.
События `Added`/`Changed` только планируют reconciliation; очередь никогда не
изменяется синхронно из собственного callback.

## Проверка в VR

1. Открыть магазин на левом контроллере и купить два одинаковых саженца и одно
   удобрение.
2. Убедиться, что три независимых предмета появились в слотах ящика.
3. При дополнительных покупках убедиться, что они появляются после освобождения
   слота и сохраняют FIFO-порядок.
4. Забрать саженец и посадить его в planting slot.
5. Забрать удобрение и применить его к растению.
6. Повторный захват уже полученного предмета не должен повторно менять очередь
   или количество в Inventory.

Автоматическая проверка выполняется общими командами репозитория:

```powershell
pwsh -NoProfile -File scripts/Test-RepositoryPolicy.ps1
pwsh -NoProfile -File scripts/Test-UnitySmoke.ps1
pwsh -NoProfile -File scripts/Test-UnityProject.ps1
pwsh -NoProfile -File scripts/Build-Android.ps1
```
